# Контекст проекта

Мы решаем кейс хакатона по поиску выгодного момента для трансграничных переводов.

## Рабочие документы

Перед изменением target, признаков, схемы валидации или метрик прочитать
`docs/experiment_spec.md`.

Решения и изменения постановки фиксировать в `docs/decisions.md`.
Если реализация расходится со спецификацией, спецификация считается источником истины,
пока расхождение явно не оформлено как новое решение.

## Цель

Для валютных коридоров RUB → TJS / UZS / KGS / AMD / KZT
нужно построить сигнальный слой, который определяет,
является ли текущий день подходящим для отправки клиенту уведомления.

Это не торговая стратегия и не задача заработка на валютном рынке.

## Данные

Основной источник — дневные официальные курсы ЦБ РФ.

Важно:
- нормировать номиналы валют;
- не считать выходные и праздники отдельными рыночными наблюдениями;
- не удалять кризисные периоды вручную;
- не допускать утечки будущей информации.

## Критическое требование

Все признаки для даты T должны вычисляться только по данным,
которые были доступны на дату T.

Бэктест только walk-forward.

## Подходы

Сравниваем как минимум:

1. Rule-based индикаторы.
2. CatBoost/LightGBM classification.
3. Regression / forecasting → trigger policy.

Сначала строим простые baseline-модели, затем усложняем.

## Метрики

Основные:
- hit rate;
- lift относительно случайного дня;
- выгода в basis points;
- количество сигналов в неделю;
- кучность сигналов;
- устойчивость во времени.

Целевая частота — примерно 1–2 сигнала на валютный коридор в неделю.
